# Решение

## Сколько заняло

Около 20 минут на реализацию и проверки после предварительного разбора задания.

## Что сделано и что не успел

Сделаны загрузка по HTTP, список матчей, три фильтра, русские статусы, местные дата и время, загрузка/ошибка/повтор/пустой список, обновление, избранное и таймер. Добавлены проверка JSON, отмена устаревших запросов и тайм-аут 15 секунд; при ошибке обновления предыдущие данные сохраняются.

Бонус — 15 тестов на фильтры, пограничные данные, форматирование времени и расчет таймера. Выполнены `npm run typecheck`, `npm run lint`, `npm test` и `expo export --platform all` (web, Android и iOS); `npm run web` отдает страницу и bundle с HTTP 200. Браузерные сценарии проверены на контролируемых HTTP-ответах из `data/matches.json`, включая ошибки и тайм-аут, на ширинах 375, 812 и 1440 px. Дополнительно проверена полная цепочка браузер → реальный HTTP-источник → 8 матчей на экране (HTTP 200, московское время первого матча 16:00). На настоящем телефоне в Expo Go не проверялось.

## Решения

«Предстоящие» включают `scheduled` и `postponed`: перенесенный матч еще не сыгран. «Завершенные» включают только `finished`; `live` и неизвестные статусы видны во «Все». Статус не вычисляется по календарю: в тестовых данных есть прошедшие даты у `scheduled`.

`startsAt: null` отображается как «Дата уточняется», `score: null` — прочерками, счет 0:0 сохраняется. Неизвестный статус получает подпись «Статус уточняется»; некорректная структура и повторные id дают понятную ошибку. `Intl.DateTimeFormat` использует часовой пояс устройства.

В исходном `MATCHES_URL` оставлена заглушка `OWNER/REPO`, поэтому адрес исправлен на публичный JSON исходного репозитория. Его можно переопределить через `EXPO_PUBLIC_MATCHES_URL`; локальная подмена данных при ошибке не используется.

По SOLID разделены правила предметной области, проверка данных, HTTP-загрузчик, хуки состояния и UI. `useMatches` принимает функцию загрузки как зависимость; компоненты получают только необходимые props. Добавлены `react-native-safe-area-context` для отступов системных областей (совместим с Expo Go), ESLint и Expo-конфигурация для проверки кода. Тесты используют встроенный `node:test`, без тестовых библиотек.

## Баги из части 2

1. Звездочки: `Boolean(indexOf(id))` превращал -1 в true, а индекс 0 — в false. Массив изменялся через push/splice и передавался в state с прежней ссылкой, поэтому React мог не обновить экран. Исправлено на `includes` и функциональное обновление с созданием нового массива; состояние общее для всех карточек экрана.
2. «Обновлено N сек назад»: интервал захватывал начальное значение seconds и постоянно выставлял 1, не использовал since и не очищался. Теперь секунды вычисляются как разность текущего времени и последней успешной загрузки, а интервал удаляется при размонтировании. Новое since сбрасывает отсчет; ошибка запроса его не сбрасывает.
